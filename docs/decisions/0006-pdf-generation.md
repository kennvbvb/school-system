# 0006 — การสร้าง PDF ภาษาไทย

- **สถานะ:** Proposed — ทิศทางตัดสินแล้ว แต่ยังไม่ได้เขียนโค้ดในรอบนี้
- **เกี่ยวข้องกับ:** ข้อ 8, FR-DOC-001..013, AC-03, NFR-003

## บริบท

แผนข้อ 25 ห้ามเริ่มทำแบบ PDF จริงก่อนมี golden sample ที่โรงเรียนรับรอง
ADR นี้จึงบันทึก **ทิศทาง** ไว้เพื่อไม่ให้ตัดสินใจซ้ำ แต่ยังไม่มีโค้ดรองรับ

## การตัดสินใจ (ทิศทาง)

### ไลบรารี

ใช้ `@react-pdf/renderer` ตามที่แผนข้อ 10.1 ระบุ

เหตุผลที่เหมาะกับข้อกำหนดนี้:

- ฝังฟอนต์ไทยได้ ทำให้ PDF ค้นหาข้อความได้จริง (ต่างจากการ render เป็นภาพ)
- ทำงานได้ใน serverless runtime ของ Vercel โดยไม่ต้องมี headless browser
  ซึ่งเป็นข้อจำกัดที่ตัด Puppeteer ออก

### ฟอนต์

Sarabun (SIL Open Font License) เก็บไว้ใน repository
ต้องตรวจสิทธิ์การใช้งานและบันทึกไฟล์ license ไว้คู่กันก่อน commit ไฟล์ฟอนต์

### สถาปัตยกรรม

- PDF renderer รับ **immutable view model** ไม่ query ฐานข้อมูลเอง (ข้อ 10.3)
  ทำให้ทดสอบได้โดยไม่ต้องยกฐานข้อมูล และรับประกันว่า PDF ที่ออกซ้ำจะได้เนื้อหาเดิม
- Preview ใช้ข้อมูลปัจจุบัน + watermark `ฉบับร่าง` + เลขที่เอกสารเป็น `DRAFT`
  (`DRAFT_DOCUMENT_NUMBER` ใน `src/domain/documents/document-number.ts` ประกาศไว้แล้ว)
- เอกสารจริงใช้ frozen snapshot เท่านั้น (ดู ADR 0007)

### ความเสี่ยงที่ต้องวัดตั้งแต่ต้น

NFR-003 กำหนดว่าชุดเอกสารต้องสร้างเสร็จภายใน 15 วินาที
Vercel serverless มี timeout ที่อาจไม่พอเมื่อเอกสารมีหลายฉบับและหลายหน้า

**ต้องวัดจริงตั้งแต่เอกสารฉบับแรก** ถ้าเกิน ให้เปลี่ยนเป็น background job + polling
ตามที่แผนระบุไว้ ไม่ใช่รอจนพบปัญหาตอน UAT

## สิ่งที่ต้องมีก่อนเลื่อนสถานะเป็น Accepted

- golden sample ที่โรงเรียนรับรองอย่างน้อย 3 ฉบับ (Q1 ใน `docs/assumptions.md`)
- proof of concept ที่แสดงว่าวรรณยุกต์และสระภาษาไทยไม่หายในตารางหลายหน้า
- ผลวัดเวลาสร้างชุดเอกสารจริงบน Vercel
