# 0001 — Technology stack และการตรึงเวอร์ชัน

- **สถานะ:** Accepted
- **เกี่ยวข้องกับ:** แผนข้อ 10.1, 16.4, NFR-008

## บริบท

แผนกำหนด stack ไว้แล้ว (Next.js + TypeScript + Supabase + Vercel) และสั่งเพิ่มว่า
"ตรวจสอบรุ่น stable และความเข้ากันได้ ณ วันที่เริ่มพัฒนา จากนั้น pin dependency
และ commit lockfile ห้ามใช้ `latest` ใน Production โดยไม่ตรวจสอบ"

การตรวจสอบพบว่ารุ่นล่าสุดของบางเครื่องมือ **ยังเข้ากันไม่ได้จริง** แม้จะประกาศ peer range กว้าง

## ตัวเลือกที่พิจารณา

1. **ใช้รุ่นล่าสุดทุกตัว** — ตรงกับคำว่า "stable ล่าสุด" ที่สุด แต่ lint ใช้งานไม่ได้จริง
2. **ตรึงรุ่นที่ทดสอบแล้วว่าทำงานร่วมกันได้** — ช้ากว่าหนึ่งรุ่นในบางตัว แต่ทุกคำสั่งใน CI ผ่านจริง
3. **รอจนกว่าทุกอย่างจะเข้ากันได้** — ทำให้เริ่มพัฒนาไม่ได้

## การตัดสินใจ

## ผลที่ตามมา

**ผลดี**

- CI ทุก step ผ่านจริง ไม่มี step ที่ต้อง `continue-on-error`
- `npm ci` ให้ผลลัพธ์เหมือนกันทุกเครื่องและทุก deployment

**ผลเสียและการรับมือ**

- ต้องติดตามว่าเมื่อใด Next.js รองรับ ESLint 10 และ typescript-eslint รองรับ TypeScript 7
  → บันทึกไว้ใน `docs/assumptions.md` ข้อ 2.11 พร้อมเงื่อนไขการทบทวน
- การอัปเกรดต้องมาพร้อม PR ที่รัน `npm run verify` ครบ ไม่ใช่การ merge Dependabot แบบอัตโนมัติ
