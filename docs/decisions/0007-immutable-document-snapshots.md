# 0007 — Immutable snapshot ของเอกสารที่ออกแล้ว

- **สถานะ:** Accepted (หลักการ) — ตารางจะถูกสร้างใน Phase 5
- **เกี่ยวข้องกับ:** ข้อ 8.4, FR-DOC-007..010, AC-04

## บริบท

AC-04 กำหนดว่า "เมื่อแก้ข้อมูลโรงเรียน ผู้ลงนาม หรือ publish template ใหม่
ไฟล์ PDF ที่เคยออกแล้ว checksum และเนื้อหาต้องไม่เปลี่ยน"

นี่เป็นข้อกำหนดที่ **บังคับรูปร่างของ schema** ตั้งแต่ต้น จึงต้องตัดสินก่อนสร้างตาราง

## การตัดสินใจ

### เอกสารที่ออกแล้วเก็บ "สำเนาข้อมูล" ไม่ใช่ "ตัวชี้ไปข้อมูล"

`issued_documents` เก็บ `snapshot_json` ที่มีค่าทุกช่องที่ปรากฏบนเอกสาร ณ เวลาที่ออก
รวมถึงชื่อโรงเรียน ชื่อและตำแหน่งผู้ลงนาม ชื่อผู้ขาย และยอดเงิน

**ไม่ใช้ foreign key ไป master data สำหรับการ render** เพราะการเปลี่ยนชื่อผู้อำนวยการ
จะทำให้เอกสารเก่าเปลี่ยนตามทันที ซึ่งขัด AC-04 โดยตรง

foreign key ยังมีอยู่เพื่อการค้นหาและรายงาน แต่ไม่ใช่แหล่งข้อมูลของการแสดงผล

### เก็บ checksum ของไฟล์จริง

`sha256` ของไฟล์ PDF ถูกบันทึกตอนออกเอกสาร
ทำให้ตรวจภายหลังได้ว่าไฟล์ใน storage ยังเป็นไฟล์เดิม และเป็นหลักฐานที่ AC-04 ตรวจได้ตรง ๆ

### การ regenerate สร้าง revision ใหม่ ไม่เขียนทับ

ถ้าต้องออกเอกสารใหม่หลังออกจริงแล้ว ให้สร้างแถวใหม่และเก็บไฟล์เดิมไว้
การยกเลิกเอกสารประทับสถานะในระบบ ไม่ลบไฟล์ (FR-DOC-010)

### การพิมพ์ซ้ำไม่สร้างไฟล์ใหม่

FR-DOC-009 — พิมพ์ซ้ำใช้ไฟล์เดิมเสมอ และบันทึก audit event `document.print`
ถ้าสร้างไฟล์ใหม่ทุกครั้งที่พิมพ์ checksum จะเปลี่ยนและ AC-04 จะล้ม

### เลขที่เอกสารจองใน transaction

`document_sequences` มี unique constraint บน `(document_type, fiscal_year_id, department_id)`
และการเพิ่มค่าต้องทำด้วย row lock ภายใน transaction เดียวกับการสร้าง `issued_documents`

เลขที่ยกเลิกแล้ว **ห้ามนำกลับมาใช้** (FR-NUM-004) — ตัวนับเดินหน้าอย่างเดียว
ไม่มีการเติมช่องว่างย้อนหลัง

## ผลที่ตามมา

- `snapshot_json` จะใหญ่ ต้องยอมรับต้นทุนพื้นที่เก็บเพื่อแลกกับความถูกต้องย้อนหลัง
- ต้องมี integration test ที่: ออกเอกสาร → แก้ master data → publish template ใหม่
  → ยืนยันว่า checksum เดิมไม่เปลี่ยน (AC-04)
- ต้องมี concurrency test ที่ยิงคำขอออกเอกสารพร้อมกันแล้วยืนยันว่าไม่มีเลขซ้ำ (AC-05)
