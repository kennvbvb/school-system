# Backup และ Restore

> **สถานะ: โครงร่าง** — ต้องกรอกค่าที่ตกลงกับโรงเรียนและ **ทดสอบ restore จริง**
> ก่อนขึ้น Production ตามแผนข้อ 14.3 และเกณฑ์ AC-10

## สิ่งที่ต้องตกลงกับโรงเรียนก่อน Production

| รายการ                               | ค่า              | ผู้รับผิดชอบ |
| ------------------------------------ | ---------------- | ------------ |
| RPO (ยอมให้ข้อมูลหายได้กี่ชั่วโมง)   | _ต้องกรอก_       | _ต้องกรอก_   |
| RTO (ต้องกู้คืนเสร็จภายในกี่ชั่วโมง) | _ต้องกรอก_       | _ต้องกรอก_   |
| ความถี่ของ backup                    | _ต้องกรอก_       |              |
| ระยะเก็บ backup                      | _ต้องกรอก_       |              |
| ระยะเก็บเอกสารที่ออกแล้ว             | _ต้องกรอก_ (Q11) |              |
| ผู้มีสิทธิ์สั่ง restore              | _ต้องกรอก_       |              |
| ผู้ตอบเหตุขัดข้อง                    | _ต้องกรอก_ (Q12) |              |

## ขอบเขตที่ต้องสำรอง

ระบบนี้มีข้อมูลสองก้อนที่ต้องสำรอง **ให้สอดคล้องกัน**

1. **PostgreSQL** — ข้อมูลธุรกรรม ทะเบียน และ audit log
2. **Supabase Storage** — ไฟล์ PDF ที่ออกแล้วและไฟล์แนบ

> ถ้าสำรองเฉพาะฐานข้อมูล จะได้ระบบที่มีแถวใน `issued_documents`
> แต่ไฟล์จริงหายไป ซึ่งเท่ากับเอกสารสูญหาย

> **GitHub ไม่ใช่ backup** ของฐานข้อมูลหรือเอกสาร (ข้อ 14.3)

## ขั้นตอนที่ต้องทำ

### เปิด automated backup

ตั้งตามแพ็กเกจ Supabase ที่โรงเรียนเลือก และบันทึกไว้ที่นี่ว่าเลือกแบบใด
แพ็กเกจฟรีไม่มี point-in-time recovery — ถ้าโรงเรียนต้องการ RPO สั้น ต้องอัปเกรด

### ซ้อมกู้คืน

ต้องทำอย่างน้อย **หนึ่งครั้งก่อนเปิดใช้จริง** และตามรอบที่ตกลงไว้

รายการที่ต้องยืนยันหลังกู้คืน:

- [ ] เข้าสู่ระบบด้วยบัญชีที่มีอยู่ก่อน backup ได้
- [ ] จำนวนแถวใน `procurements`, `issued_documents`, `audit_events` ตรงกับที่คาด
- [ ] ไฟล์ PDF ใน storage เปิดได้ และ **checksum ตรงกับ `sha256` ในฐานข้อมูล**
- [ ] ตัวนับใน `document_sequences` ไม่ถอยหลัง (ถ้าถอย เลขเอกสารจะซ้ำ)
- [ ] RLS policies ยังทำงาน — ทดสอบด้วยบัญชีที่ไม่มีสิทธิ์

รายการที่สามสำคัญที่สุด เพราะเป็นสิ่งเดียวที่พิสูจน์ว่าเอกสารยังเป็นฉบับเดิม (AC-04)

## ความเสี่ยงเฉพาะของระบบนี้

**ตัวนับเลขเอกสารถอยหลัง** — ถ้ากู้คืนฐานข้อมูลไปยังจุดก่อนหน้า
`document_sequences.current_value` จะถอยกลับ แล้วเลขที่เคยออกไปแล้วจะถูกออกซ้ำ
ซึ่งขัด FR-NUM-003 และ FR-NUM-004 โดยตรง

**ต้องมีขั้นตอนตรวจและปรับตัวนับให้สูงกว่าเลขสูงสุดที่เคยออกจริงเสมอ หลังกู้คืนทุกครั้ง**
